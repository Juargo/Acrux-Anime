# ADR-0027: CI/CD: GitHub Actions y despliegue en Vercel

- **Estado:** Aceptado
- **Fecha:** 2026-10-27
- **Participantes:** Jorge (stakeholder, Product Owner y desarrollador), Claude (analista)
- **Origen:** Sesión con el stakeholder, 2026-10-27

**Reemplaza:** la lista de CI de ADR-0018 («Infraestructura y CI») y la fila «CI» de ADR-0003. Se ordenan las mismas verificaciones por costo y frecuencia.

## Contexto

- El repositorio ya trabaja con PRs hacia `main` y Conventional Commits.
- El repositorio es **público** (decisión del 2026-10-27): GitHub Actions no tiene tope de minutos, pero **los logs y los artefactos de Actions son visibles para cualquiera**. Ningún flujo puede imprimir datos personales ni secretos, ni guardar datos de producción como artefacto.
- Vercel crea un despliegue de vista previa por PR (ADR-0020).
- Las migraciones de Prisma deben aplicarse **antes** de publicar el código que las usa.

## Opciones consideradas

| Opción | Comentario |
|---|---|
| **GitHub Actions + Vercel (CLI para producción)** | Gratis; las vistas previas automáticas de Vercel sirven para las pruebas E2E; la producción se publica desde Actions después de migrar. |
| Solo la integración Git de Vercel | Más simple, pero publica en paralelo a las migraciones y no ejecuta las pruebas antes de publicar. |
| Otro CI (CircleCI, GitLab) | Sin ventajas frente a Actions para un repositorio en GitHub. |

## Decisión

### Flujo de trabajo

- **Trunk-based development** con ramas cortas y PRs hacia `main`, fusionados con *squash*.
- `main` protegida: requiere el pipeline en verde; no se permite *push* directo.
- **Conventional Commits** verificados con commitlint; **release-please** genera el changelog y las versiones.
- husky + lint-staged en local (Biome sobre los archivos modificados).

### Pipeline por PR (cada *push*)

| Etapa | Herramientas |
|---|---|
| Calidad | `biome ci`, `tsc --noEmit`, `dependency-cruiser` (ADR-0019) |
| Pruebas | Vitest: unitarias e integración de la API contra Postgres en un *service container* (ADR-0029) |
| Contrato | `openapi:check` (el contrato emitido coincide con el del repositorio, ADR-0018) y Schemathesis contra la API local levantada en el job |
| Seguridad | gitleaks (secretos), `pnpm audit --audit-level=high`, Semgrep CE (SAST) |
| Build | Build de `web`, `api` y `landing` |
| E2E | Playwright (humo) contra la **vista previa de Vercel** del PR, con AniList simulado (ADR-0029) |

### Despliegue a producción (al fusionar en `main`)

1. Repite las etapas de calidad, pruebas y build.
2. `prisma migrate deploy` contra producción. Las migraciones son compatibles hacia atrás (ADR-0022).
3. `vercel deploy --prod` con la CLI de Vercel; la publicación automática de producción desde Git queda desactivada.
4. Prueba de humo contra `/api/health` y la página de inicio; si falla, se revierte con `vercel rollback`.

### Trabajos programados (semanales)

- **DAST:** ZAP en modo *baseline* contra la vista previa de `main` (ADR-0018). Es semanal porque tarda y genera ruido, no por costo.
- **Respaldo:** `pg_dump` cifrado de producción, subido a un bucket privado; nunca como artefacto de Actions (ADR-0022).
- **Dependabot:** actualizaciones semanales agrupadas de npm y de GitHub Actions.

### Cadena de suministro

- Acciones de GitHub fijadas por **SHA**, no por etiqueta.
- `pnpm install --frozen-lockfile`.
- Secretos solo en GitHub Actions y Vercel, separados por entorno; `permissions:` mínimos en cada flujo.
- Repo público: los PRs desde *forks* no reciben secretos (`pull_request`, nunca `pull_request_target` con código del fork); los flujos con secretos exigen aprobación del entorno `production`.

## Consecuencias

- **Positivas:** nada llega a producción sin pasar las pruebas; las migraciones siempre preceden al código; costo cero.
- **Negativas / riesgos:**
  - El DAST semanal detecta tarde los problemas que no cubren las pruebas de cada PR.
  - Publicar con la CLI requiere un token de Vercel en los secretos de GitHub.
- **Acciones derivadas:** crear los flujos `ci.yml`, `deploy.yml` y `weekly.yml`; configurar la protección de `main`; desactivar la publicación automática de producción en Vercel.
